# Spacegroup Atlas v0.6 — Rendering and scaling repair

Offline-capable WebGL2/WebXR room-scale educational tool for Meta Quest 3 and desktop browsers. This is a replacement for v0.5, not an additive patch.

## Installation

Extract `Spacegroup_Atlas_Quest3_v0.6.zip` and copy its **contents** into the root of your existing GitHub Pages repository, overwriting the old `index.html`, `main.js`, `assets-inline.js`, `volume-inline.js`, `style.css`, `README.md`, and any matching assets. Keep `assets/` alongside `index.html` rather than uploading the ZIP itself. No external CDN, Blender plug-in, npm install, or local server is needed at runtime. After publishing, hard-refresh Quest Browser to bypass older cached JS. The HTML references version-tagged v0.6 scripts.

You can also open `index.html` locally on a desktop using the embedded binary assets as fallbacks.

## What was broken in v0.5, and what changed

**Both fills black / invisible** — The original 2D PNG upload path used `UNPACK_FLIP_Y_WEBGL = true`. This setting persisted when `gl.texImage3D()` was called to upload the solid and Kenney-derived 3D textures. The WebGL2 specification does not allow flip-Y or premultiply-alpha pixel store modes with typed-array `texImage3D` uploads. The browser rejected those uploads with `INVALID_OPERATION`, so shaders sampled incomplete / uninitialized textures, which rendered black or empty. v0.6 explicitly disables both modes before each `texImage3D` upload, checks the GL error immediately afterward, and fails visibly on a bad upload.

**Low-detail / illegible 2D fill** — The obsolete 48^3 sampled Kenney field has been removed from the wall rendering path. Each symmetry-transformed full-cell wall now samples the **original full-resolution 2D PNG** directly, preserving its intended geometric pattern and original alpha transparency. Walls still extend several lattice radii and blend together. The default wall-opacity control is now **22%**, with fine 2%-step adjustment for studying overlapping see-through sheets. Wall positions are generated by the space-group operations; selected square-face texture-coordinate transformations are conservatively made invariant under mirror/quarter-turn stabilizers. The 2D mode does not use the 3D volume samples.

**Period slider visually inert** — v0.5 scaled all cell positions, motif sizes, and distances **about the user's eye**, which leaves the projected view nearly scale-invariant. The new period slider keeps the **center of the user's current lattice cell** fixed in world space and scales the neighboring lattice and motif relative to that point. Visible size and spacing now change. For very large changes in period, nearby walls may still sweep through the user; the walls are non-colliding. The slider controls actual meters, not a cosmetic number.

## Representation modes

1. **Contained 3D motifs:** Kenney archer, tree, target; exact orbit instances and left-trigger body-locked motif handling. A separate, optional generator demonstration is available **only for motifs**.
2. **2D Fill:** Five opaque or five line-pattern PNGs from Kenney on several radii of full-cell walls in three orientations. Native texture alpha and adjustable overall opacity. The walls are intentionally non-colliding, so you can move through them and inspect visual overlap and moiré. No animation.
3. **3D Fill:** One opaque section through a **fixed, periodic solid RGB voxel field**, following the headset (or fixed when follow is disabled). The depth control offsets the plane in front of the eye for seated exploration. The exterior toggle displays the six textured exterior faces of a **single** primitive cell, replacing the slice rather than drawing a translucent stack. No animation.

Three solid choices: oak (bent growth rings), walnut (burl, dark knots), and strata (intersecting mineral laminae). Each is a real 64³ RGBA voxel field with depth variation, precomputed offline and transformed under the selected crystallographic operations. Oak and walnut should look like solid wood rather than volumetric clouds.

**Material provenance:** These voxel fields are independently generated **mathematical adaptations** of visual structures found in the previously supplied `.blend` files, not exact Blender shader evaluations. See `tools/build_solid_textures.py` and `solid_texture_sections.png` for the reproducible functions and slices. The source `.blend` files and CGTOON collections are not bundled. Filtering and linear interpolation introduce approximation between voxel centers; finite cropped fields are not globally space-group invariant, although the underlying 64³ field is symmetrized at voxel centers.

## Controls / performance

- Desktop: WASD move; mouse drag look; Q/E turn; R/F vertical movement; C grab; [ and ] group; M motif; H VR-style menu.
- Quest 3: left thumbstick moves, right stick turns/flys or navigates the opened menu, left trigger grabs/releases a motif, right B opens/closes menu.
- Recommended: `Quest safe` radius on large point groups, particularly Pm-3m (48 copies per primitive cell). Do not assume 48 operations across six full taxicab radii will run comfortably in Quest 3.
- Cell period is 0.10–2.50 m. The observer's current-cell **center** is the rescaling anchor; this is deliberately not an eye-centered uniform scale.
- To see internal structure independently of group symmetrization, choose **P1** first, then experiment with P4₁, Pmmm and cubic groups.
- The comfort-floor plane follows horizontally at the tracked floor height, with a finite visual fade; it is not Quest's Guardian polygon.

## Regression testing

The build was tested in a **real Chromium WebGL2 browser**, using `tools/browser_smoke.py` in an Xvfb display. The test samples actual rendered pixels, checks 0.6 m vs 1.8 m period for a visible difference, confirms opaque vs line wall images differ, checks all three materials and the exterior are nonblack, and queries WebGL for errors. Result: **PASS (no GPU errors)**. This validation uses a desktop OpenGL implementation, not a Quest 3 headset; in-headset visual quality, motion-to-photon behavior, and frame rate still need testing.

Additional checks: `node tests/mathematical_checks.js` (all eight groups, screw symmetry, volume voxel-center equivariance, scale anchor, fill mode toggle), `node --check main.js`, and `python tools/test_shaders.py` (five shader programs compiled and linked under GLES3).
